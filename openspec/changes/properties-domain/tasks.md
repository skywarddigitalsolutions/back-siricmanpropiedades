# Tasks: Properties Domain (back)

## Reconciliation Notes (spec ↔ design, applied before this task breakdown)

- **Publication transition matrix**: both `specs/property-management/spec.md` and `design.md` now use the same broad matrix: `publish` allowed from `draft` or `archived` → `published` (sets `firstPublishedAt` only if it is still null); `archive` allowed from `draft` or `published` → `archived`; `unpublish` allowed from `published` or `archived` → `draft` (`firstPublishedAt` never cleared). Any other combination (including same-state) is `400 Bad Request` with state unchanged. The spec's "surfaced for confirmation" note was removed; design's "archived -> published requires unpublish then publish" rationale was removed and replaced.
- **External contract names**: design's public filter query parameters were renamed to match the spec (`pmin`/`pmax` → `priceMin`/`priceMax`) throughout `design.md` (DTO contract, data-flow example, index rationale, builder rules, error-mapping table, testing-strategy table).
- **Public `featured` filter (open question, NOT resolved here)**: `design.md`'s `PublicPropertyFiltersDto` originally included a `featured?` toggle that the spec's "Public Listing Filters" requirement does not list. This is a product-scope question, not a naming mismatch, so it is **not implemented** by the tasks below — see `## Open Questions Carried Forward`. `design.md` was updated to explicitly exclude it from the DTO contract for this change.
- **Business-rule/uniqueness violations**: both artifacts already agree — these are `400 Bad Request` in both specs and in `design.md`'s error-mapping table (duplicate neighborhood, hard-delete-of-published, invalid transitions, duplicate deal status). No change needed.
